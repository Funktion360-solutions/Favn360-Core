# Contributing to Favn360

Thank you for your interest in Favn360.

Favn360 is developed and maintained by Funktion360.

Favn360 is **source available, not open source**. Contributions are welcome where Funktion360 has enabled community contributions for the relevant repository.

## Before contributing

Please read:

- `LICENSE`
- `CLA.md`
- this `CONTRIBUTING.md`

By submitting a Contribution, you agree that the Contribution is subject to the Favn360 Contributor License Agreement (`CLA.md`).

Do not submit a Contribution if you do not have the necessary rights to do so.

## Ways to contribute

Depending on the repository, contributions may include:

- bug reports;
- documentation improvements;
- accessibility improvements;
- translations;
- tests;
- bug fixes;
- performance improvements;
- feature proposals;
- source-code contributions.

## Issues

Before opening an issue, check whether an existing issue already covers the problem.

For bugs, please include where relevant:

- Favn360 version or commit;
- operating environment;
- steps to reproduce;
- expected behaviour;
- actual behaviour;
- relevant logs or screenshots.

Do not include personal, confidential, sensitive, production, citizen, client, patient, case, or otherwise protected information.

## Security vulnerabilities

Do not publicly disclose a security vulnerability through a GitHub issue if doing so could put users, systems, or data at risk.

Use Funktion360's designated private security-reporting channel where available.

## Pull requests

Pull requests should:

1. have a clear purpose;
2. be limited to the relevant change where reasonably possible;
3. follow the existing architecture and coding conventions;
4. include relevant tests where appropriate;
5. avoid unrelated formatting or dependency changes;
6. contain no confidential or proprietary third-party material;
7. comply with `CLA.md`.

Funktion360 may request changes before accepting a pull request.

## Architecture

Contributions should respect Favn360's established:

- application architecture;
- database architecture;
- authentication and authorisation model;
- security boundaries;
- API conventions;
- data model;
- design system.

Large architectural changes should normally be discussed before implementation.

## Dependencies

Do not introduce a new dependency without considering:

- licence compatibility;
- maintenance status;
- security;
- bundle or runtime impact;
- necessity.

Dependencies with licensing terms incompatible with Favn360's licensing model may be rejected.

## AI-assisted contributions

AI-assisted development tools may be used where legally permissible.

Contributors remain responsible for ensuring that submitted material:

- can legally be contributed;
- does not knowingly reproduce incompatible copyrighted material;
- complies with this Contributor License Agreement;
- meets the same quality and security requirements as other Contributions.

## Review

Funktion360 has no obligation to accept a Contribution.

A Contribution may be:

- accepted;
- modified;
- rejected;
- postponed;
- replaced by another implementation.

Acceptance of a Contribution does not create an employment, partnership, agency, or commercial relationship between the contributor and Funktion360.

## Licence

Contributing to Favn360 does not change the licence applicable to your use of Favn360.

Commercial and organisational use remains subject to the applicable Favn360 licensing terms.

Thank you for contributing to Favn360.
